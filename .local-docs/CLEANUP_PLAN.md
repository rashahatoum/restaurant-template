## Details

### P0 — Next.js security patch
- `npm audit --omit=dev` reports a **critical** advisory for `next` 16.0.0–16.4.0: RCE in the image optimizer with SVGs, a Server Actions DoS, and RCE in `use cache` with typed arrays. `next build` also prints the warning.
- Fix: bump `next` and `eslint-config-next` to the latest patched **16.4.x** (16.4.3 was published at audit time), on a branch, then run lint, type-check, and build, then smoke-test. A patch-level bump inside the same minor version is low-risk for breaking changes.
- No other production advisories were reported.
- **Done 2026-10-25** on `fix/next-security-patch` (commit `526249e`). Lint, type-check, and build pass; `npm audit --omit=dev` reports 0. `main` is still on 16.3.5 until merged.

### 1 — `typecheck` script
Add `"typecheck": "tsc --noEmit"`. The requirements ask for type-checking, and today the only way is `npx tsc`.

### 2 — Uncommitted change
`HeroImageSequence.tsx` has a working-tree change that collapses a comment banner (`/* ====== GENERATE FRAMES`). It is cosmetic and inconsistent with the other banners. Recommended: revert it. The owner decides.

### 3 — Spacing scale (`--spacing: 1px`) bugs
These classes look like they were written for Tailwind's default 4px scale:
- `NavBar.tsx` (mobile): `[&>svg]:size-5` gives **5px icons**; `gap-1.5`, `gap-2`, `px-6 py-5`, `pb-10 pt-4` give 1.5–10px. The hamburger button has leftover `flex flex-col gap-1.5`, and the logo link has leftover `font-display text-2xl font-bold`.
- `Hero.tsx`: `h-2` / `sm:h-3` / `lg:h-4` underline (2–4px, possibly intentional), `mt-2`, `gap-2`, `px-2`, `gap-2.5`, `sm:gap-3`, `lg:gap-3`, `lg:h-14`, `xl:h-16` (14–16px button heights are almost certainly wrong).
- Likely not generated by Tailwind at all: `lg:max-w-760px`, `xl:max-w-820px`, `lg:min-h-130px`. Replace with `max-w-760` and so on, or arbitrary values.

Fix each class to the intended pixel value, then compare visually against the design reference.

### 4 — Hard-coded colors
`text-white`, `border-white/30` (Hero features), `bg-black/60` (nav bar). Add tokens such as `--theme-overlay` and `--theme-divider` to the theme and use them.

### 5 — Body font
`font-body` is repeated on elements while `<body>` uses Tailwind's default sans font. Set the body font once. This affects any text without an explicit font class.

### 6 — NavBar accessibility
- Close the menu on link click. This matters most for hash links on the same page, which currently leave the overlay open.
- Close on Escape, move focus into the overlay and back to the toggle, and lock body scroll while open.
- Add `aria-expanded` and `aria-controls` on the toggle.
- Use `href` instead of the index for keys.
- Keep it a Client Component, but only the menu toggle and overlay need to be client-side. The desktop links could be server-rendered if this ever matters.

### 7 — Config-driven navigation
Nav links (with JSX icons) live in `page.tsx`, and "اطلب الآن" is hard-coded twice in `NavBar.tsx`. Every new page would need the links again. Move links to config with icon **keys** (as the hero features already do) and map keys to icons in the component.

### 8 — Typed config
Export a `RestaurantConfig` type and use `as const satisfies RestaurantConfig`. Make `theme` a union of the defined themes and make the feature `icon` a union so `featureIcons[...]` doesn't need a cast. Split animation tuning out of `hero` when Phase 6 defines the motion config. Don't over-split before then.

### 9 — Hero layout
- The 2026-10-02 decision says "flow layout, no positional offsets", but the code positions the spit absolutely (`absolute inset-y-0 left-40 w-[45%]`). Decide which is intended (open question Q6), then update the code or the decision.
- Gutters stack: the wrapper has `md:px-[8vw]`, Hero has `ps-[8vw]`, and the nav has `px-[8vw]`. Use the `page-gutter` token once.
- The `md:grid` in `page.tsx` has no effect because the header is `absolute`. Simplify it.
- Move `<NavBar />` from `page.tsx` into `layout.tsx` so every route gets it once (owner-approved to do together with this item).
- `whitespace-nowrap` on the `h1`/`h2` and `w-[80%]` content over a 45%-wide spit risk overflow and overlap at 360px.
- Primary CTA: the WhatsApp icon and `/menu` target don't match. Both buttons are identical, so give the secondary button a distinct style. Extract a `Button` once there are two or more uses (there are now).

### 10 — HeroImageSequence (interim)
Only worth doing if the production hero stays as-is for a while. Otherwise Phase 6 replaces it.
Clear the interval on unmount, skip autoplay under `prefers-reduced-motion`, preload frames, move `priority` to the first frame only, replace the clickable `div` with a `button` or remove click, and take frames via props instead of reading config.

### 11 — Unused items
- `public/assets/imgs/shawrma-hero.webp` (257 KB) isn't referenced. Delete it after confirming it isn't needed as the future static hero fallback. It may be exactly that, so check before deleting.
- `restaurantConfig.hero.media.type` is unused. Keep it and repurpose it as the motion `kind` in Phase 6.
- `restaurantConfig.contact` is unused but needed for Phases 4–5. Keep it.

### 12 — Lab & `three`
Keep the lab until the Phase 6 decision. Afterwards, promote the winning engine (plus `useSpin`) to `components/motion/`, then delete or keep the lab. If B is not chosen, remove `three` and `@types/three`. Today `three` is in `dependencies` but is only loaded on demand by a dev-only route, so it is never loaded in production.
